# hf_ally changelog (development history, newest first is NOT guaranteed; see git tags)

A player-side, AI-run ship in battle for Highfleet Steam 1.163 (Rust, standalone; port to a QoL fork branch once the sites are confirmed).
Background, addresses and open questions: `hf_notes/docs/findings/battle-ally.md`.

* **v0.12.10 (telemetry):** dead-node diagnostic. Two read-only hooks in the game's per-frame dead-node collector (`0x1401be274` nodes, `0x1401be2f8` joints) write `Modloader/logs/hf_ally_deadnode.log` (class from RTTI, state, ids, master, name, raw bytes, which ship part it is) just before the game's fatal `Collect_dead ... m_master` assertion; nothing is changed or skipped. Also drops the `ammo_flags` column (it was the AI flag block, not ammo). Needs `telemetry: true` in the config; installed from the telemetry build only.
* **v0.12.9 (telemetry):** new column `gun_ammo` = the ammo each gun is set to (`index:item_name/extra_index`, from gun part `+0x850`/`+0x854` and the `AmmoDefList` name), so AP / proximity / incendiary can be told apart. Not yet confirmed in game.
* **v0.12.8 (telemetry):** the player's `P` row is now sampled at 30 Hz (was 10 Hz) for aim and dodge timing. Other ships (`E` rows) and the bodies `C`/`B` rows stay at 10 Hz; births and deaths are still per frame.
* **v0.12.7 (telemetry):** every frame the flying bodies (shells, rockets, missiles, flares) are scanned: `N` row when a body appears (logic, stats, position, velocity, ttl, owner ship, target ship, oid), `X` row when it is gone (last position and velocity = roughly the impact point). Constant bodies (logic 0/200/400/910/3506) are listed once as `K`. New columns `owner_id`, `owner2_id`, `oid` in the bodies CSV.
* **v0.12.6 (telemetry):** a new battle is detected when the player's ship changes or the clock jumps, so one CSV set is one battle (before, three battles shared a file when the roster never emptied). Summary script: aim report from the cursor floats `vc2/vc3` (a world-aligned aim offset, -100..100; while firing, `atan2(vc3, vc2)` pointed at the nearest armed enemy within 3 degrees median).
* **v0.12.5 (telemetry is now a cargo feature):** the telemetry code is compiled in ONLY with `--features telemetry` (the user's own build: `cargo xwin build --release --features megalog,telemetry`, shipped as `hf_ally_v0.12.5_debug_telemetry.dll`); a plain or `megalog`-only build contains none of it and ignores the `telemetry` config key, so tester builds carry no telemetry. Also: a `name` column (the ship design name, std::string at creature +0xa90, found from the v0.12.4 N rows).
* **v0.12.4 (telemetry: everything):** the telemetry now writes three CSVs per battle session. `hf_ally_telemetry_*.csv` gains per-ship part counts, summed part health, fuel, crew, the AI steering waypoint, AI flags, raw physics fields, and for the player the raw mouse, candidate virtual-cursor floats, wave timer and raw control bytes. `hf_ally_parts_*.csv` is the damage log (every part of every ship when first seen with its oid, every health/state change, parts leaving the list, and all text strings inside each ship object to find the ship name). `hf_ally_bodies_*.csv` counts flying bodies by logic id each sample and lists every body with a target (missiles, torpedoes) with position, velocity and who it is aimed at. Still read-only, no game calls.
* **v0.12.3 (telemetry, no behaviour change):** config `telemetry` (default false) writes `Modloader/logs/hf_ally_telemetry_<unix>.csv` per battle: about 10 rows/s of game time for the ship you fly (`P`) and every other live ship (`E`): position, side, state, target, gun/Zenith/flare launcher rounds, control bytes, boost, LMB/RMB, the game's raw mouse values (and their per-frame sum), zoom. F9 drops a marker row (`M`). Read-only. The battle-manager hook is now installed when `spawn_ally` OR `telemetry` is on, so `spawn_ally: false` gives a solo-flying capture. Summary: `python3 tools/telemetry_summary.py FILE.csv`. Not logged: velocity/acceleration (derive from positions), health, world aim direction (camera not located).
* **v0.11.0 (diagnostics, no behaviour change):** the first hf_ally line of every log is now `hf_ally v<version> (build <UTC time>)`, so a tester's build can be told at a glance. Every build installs a crash reporter (panic hook + exception handler): a fatal exception writes `CRASH ...` lines (exception code, module+offset with the Ghidra address for the game's own exe, registers, stack frames, and the name of the hf_ally hook that was running, if any) and flushes the log, because the modloader buffers its log file (flexi_logger `BufferAndFlush`) and loses the last moments of a crash. **Debug build** (`cargo xwin build --release --features megalog`, ship as `hf_ally_v0.11.0_debug.dll`, the banner says `DEBUG BUILD`): an extra unbuffered file `Modloader/logs/hf_ally_megalog_<unix time>.log` with a heartbeat every 0.5 s (game clock, scene state, counts, running hook), every GUI click, every change of the scene state, every spawn and pre-combat seam, no line budgets, and a minidump `Modloader/logs/hf_ally_crash_<unix time>.dmp` on an unhandled crash; a watchdog thread flushes the normal log every 0.3 s. Testers send the newest `Highfleet_*.log`, `hf_ally_megalog_*.log` and `hf_ally_crash_*.dmp`. The megalog grows by roughly 1 MB per hour of idle play plus the probe lines in battles.
* **v0.10.x (sounds):** radio voice lines through the game's own sound function `playSFXSound_` (`0x1402e30e0`): ally joins = `mission_start_01..03`, F8 retreat order = `mission_danger_01`, ally leaves by retreating = `mission_end_01..03`, ally destroyed = `radio_stall_01` / `radio_lost_energy_01` (config `ally_sounds`, default true; off when the entry bytes differ, e.g. with `hf_probe` loaded). v0.10.0 was silent (volume pointer 0.0), v0.10.1 audible, v0.10.2 detects a destroyed ally (it leaves the roster, state is not 6/7), v0.10.3 adds the retreat line. Mechanism: `hf_notes/docs/sound.md`.
* **v0.2.0:** `spawn_ally` (default false) brings the next reserve ship into the battle as an AI wingman, once per battle, via the vanilla deploy function (findings note: "Revised plan"). Hooks the per-frame battle manager `0x1402cc260`. `log_creatures` (default false) re-enables the noisy per-frame creature log. The spawner hook `0x1402672c0` still logs `ALLY SPAWN` lines (template, caller RVA).
* **v0.1.1 (log-only, no behaviour change):** entry hooks on the Creature add-to-level routine `0x14006bf60` (`ALLY ADD|REMOVE` lines: side, AI flag, state, controlled, vector sizes) and on the spawner `0x1402672c0` (`ALLY SPAWN`: template, class, caller RVA). Lines carry the level name; the budget resets per level. v0.1.0 had only the first hook.
* Config `Modloader/config/ally.json`: `{ "enabled": true, "max_lines": 600, "spawn_ally": false, "ally_delay_seconds": 1.5, "log_creatures": false }` (created on first run; missing keys take these defaults).
* Build: `cargo xwin build --release` (msvc target from `.cargo/config.toml`); copy to `../hf_ally_build/hf_ally_v<version>.dll`.
* Install: copy the DLL into `<game dir>/Modloader/mods/`; remove any older `hf_ally_v*.dll` first. Do not run it together with another mod hooking `0x14006bf60` (the DLL refuses to install if the bytes differ).

## Side patch: `intercept_ignore_oids` (branch `side/ignore-intercept-oids`, never merged to master)

For modders who made an anti-air missile (a Sprint) strategic-launchable by giving it the category bit `0x8000000` in `OL.seria`. In the missile-vs-ship arcade scene the AI of **both** sides then counts that missile as a strategic launch to intercept, even when its own side launched it: the CIWS and the anti-air launchers fire at it and it takes priority over the real incoming missile.

Config (`Modloader/config/ally.json`), empty by default (= vanilla):

    "intercept_ignore_oids": ["MDL_MISSILE_03"]

`MDL_MISSILE_03` is the stock R-9 Sprint; use the exact `m_oid=` names from `OL.seria` (case-sensitive, one entry per part; a clone with its own oid needs its own entry). The log line `INTERCEPT candidate: strategic-launch body oid=...` lists the first 12 distinct oids the AI saw as strategic launches, so a wrong name shows up after one battle. A listed part is never put on any AI ship's interception list; the AI picks the next real threat. It works without `spawn_ally`. Log lines: `hf_ally: AI ignores these parts...` at start and `INTERCEPT ignore: body=... oid=...` the first time each missile is skipped. Untested in play as of v0.12.11-ignoreoid.1. Site: `0x140062812` (`docs/findings/ai/ai-intercept-targets.md` in hf_notes).
